# 需求規格與選題說明（Requirements Specification）

## 1. 專案願景與問題定義

**專案名稱**：程式觀念實驗室（Concept Lab）  
**副標題**：從物件導向到 MVC 與低耦合設計  

許多初學者在掌握變數、條件判斷與函式後，進入中小型專案時仍會遇到以下瓶頸：
- 把所有變數與邏輯都塞在單一函式或全域狀態中，改一處壞三處；
- 知道類別（`class`）的語法，卻不清楚為什麼要區分藍圖與物件個體、為什麼需要 `private` 保護狀態；
- 不了解「繼承 vs 組合」、「抽象類別 vs 介面」、「耦合與內聚」如何真正影響後續修改成本；
- 進入網頁開發後，面對 MVC（Model-View-Controller）分層架構時，無法與前面學過的物件導向與職責分離觀念連貫起來。

本專案藉由**有來源依據、結構統一的 LLM Wiki** 搭配**可視化概念模擬互動實驗室**，以清楚的 C# 範例為載體，引導讀者建立通用軟體設計觀念。

## 2. 選題理由與八章學習路線

初版固定收錄八個循序漸進的核心主題，每章挑選最貼近直覺且互不重複的生活／系統情境：

| 章節 | 主題 | 情境 | 核心觀念 | 承接關係 |
| :--- | :--- | :--- | :--- | :--- |
| 01 | 類別與物件 | 學生名冊 | 藍圖 vs 個體、欄位、屬性、方法、建構式 | 建立物件思維起點 |
| 02 | 封裝 | 銀行帳戶 | 隱藏內部狀態、透過方法把關規則與精度 | 保護物件不變量 |
| 03 | 繼承與組合 | 交通工具與引擎 | `is-a` 與 `has-a`、設計取捨 | 建立物件間關係 |
| 04 | 多型 | 不同動物發聲 | 共同型別、`virtual` / `override`、動態分派 | 以統一介面操作異質物件 |
| 05 | 抽象類別與介面 | 圖形及繪製能力 | 共用實作基底 vs 行為契約 | 為低耦合準備抽象邊界 |
| 06 | 耦合與內聚 | 訂單計算及通知 | 職責分離、依賴方向、替換實作修改範圍 | 評估程式可維護性 |
| 07 | MVC | 圖書查詢 | 網頁請求流程、Model / View / Controller 分工 | 延伸至 Web 系統架構 |
| 08 | 整合與重構 | 待辦事項系統 | 從混合腳本整理分工、因應新需求 | 綜合演練前七章觀念 |

**擴充設計考量**：待初版八章與來源查核完成後，將於獨立階段實作第 09 章「依賴注入（Dependency Injection）」，驗證本系統的 Wiki 擴充性與自動化索引機制。

## 3. 教材固定結構與互動設計需求

### 3.1 每篇教材固定九段結構
1. **問題情境**：先呈現具體痛點，再引出觀念需求。
2. **學習目標**：條列 3–4 項可檢核的學習成果。
3. **觀念圖解**：以文字標示配合圖表呈現結構與資料流向。
4. **C# 範例**：提供可分檔檢視、含行號、語法高亮與重點行標示的 C# 程式碼。
5. **預期結果**：清楚展示執行輸出與記憶體狀態變化。
6. **修改需求的比較**：比較「未套用該觀念」與「套用後」面對需求變更時的修改範圍。
7. **常見誤解**：釐清初學者常混淆的迷思。
8. **小練習與解析**：提供自我測驗題目與可展開的詳解。
9. **相關概念及資料來源**：連結前置／延伸章節，並附上已登錄之來源依據。

### 3.2 互動實驗室需求（第一階段完成第 01、02 章）
- **明確區分技術本質**：清楚標示網頁互動為「TypeScript 前端概念模擬」，而教材主體為「C# 程式碼」，不誤導讀者以為瀏覽器正在執行 .NET CLR。
- **第 01 章（學生名冊）**：
  - 可操作並觀察兩個獨立學生物件（如林小安、陳以樂）的建立過程與獨立記憶體狀態。
  - 可觸發建構式與更新成績方法，同步高亮對應的 C# 程式碼行並提供逐步播放與重置。
- **第 02 章（銀行帳戶）**：
  - 支援存款、提款、預設測試案例（含負數、零元、超額提款等非法輸入）。
  - 採用整數分（cents）計算確保精度，失敗操作必須維持餘額不變並解釋攔截原因。
  - 連動操作結果、帳戶狀態、對應 C# 行號與預期結果比對。

## 4. 技術架構與交付驗收條件

### 4.1 靜態部署與離線可用性
- 輸出純靜態 `dist/` 產物，相容 GitHub Pages repository 子路徑（`vite.config.ts` 設定 `base: './'`，路由使用 `HashRouter`）。
- 所有教材（`wiki/`）、來源登錄（`sources/`）、範例程式（`examples/csharp/`）與規範文件（`docs/`、`AGENTS.md`）皆透過建置期靜態載入，部署後不依賴任何後端伺服器、資料庫或外部 API Key。
- 學習進度與收藏儲存於瀏覽器 `localStorage`，提供「還原預設狀態」功能，且在隱私模式或禁用儲存空間時頁面仍可正常運作。

### 4.2 第一階段驗收條件（已完成）
1. `AGENTS.md` 與 `docs/requirements.md` 先行建立並為開發依據。
2. 可正常瀏覽三大入口：「教材知識庫」、「教學簡報」、「資料來源與製作流程」。
3. 八章索引完整呈現；第 01、02 章具備完整九段式教材、獨立 C# 範例檔與互動實驗室。

### 4.3 第二與第三階段驗收條件（全八章 Ingest、HTML 簡報、Workflow 與紀錄）
1. **來源 Ingest 與八章補齊**：至少完成 5 篇主題來源實地讀取並建立 `wiki/sources/*.md`（目前已完成 8 篇主題／補充來源與 2 篇方法論參考）；八章教材（`01`–`08`）全部升為 `verified` 且每章配有互動實驗室與 2 題檢核問答。
2. **教學 HTML 簡報（18–24 頁）**：
   - 從 `wiki/concepts/*.md`、`examples/csharp/` 與 `sources/registry.json` 單一資料來源同步產出 21 頁簡報（同時支援站內 `#/slides` 與獨立檔案 `public/slides.html`）。
   - 共用相同主題 ID、摘要、範例 ID、來源 ID 與行號切片（`slideExampleId` + `slideLineRange`），避免另寫矛盾版本。
   - 支援前後翻頁、頁碼／進度、章節目錄、全螢幕（含權限受限時的「專注滿版閱讀模式」替代方案）、剪貼簿備援複製、回到對應完整教材、安全鍵盤左右鍵翻頁（輸入框與程式碼操作區不誤觸）、手機可讀版面，以及自動展開全部投影片的 `@media print` 另存 PDF 版面。
3. **Workflow 圖與節點規格（`docs/workflow.md`）**：
   - 明確區分 A–F 六階段（取得來源與登錄 → Ingest 與整合 → 觀念與程式碼檢查 → 生成教材與 HTML 簡報 → 瀏覽與建置檢查 → 公開部署與反思）與退回修正回路，並清楚區分「工作流程圖」與「概念知識關聯圖」。
4. **真實紀錄與繳交清單**：
   - `docs/process-log.md`、`docs/verification.md`、`docs/reflection.md` 僅記載真實執行結果與環境限制（無 `.NET SDK` 標示 `unverified-no-dotnet`，受阻來源標示 `unavailable`）。
   - `docs/submission-guide.md` 提供完整 8 項檢核表、可轉 PDF 報告草稿與 11 處建議截圖清單，區分已完成事實與待使用者補填項目。

### 4.4 後續第四階段保留項目
- 於獨立階段新增第 09 章「依賴注入（Dependency Injection）」，完整走過一次 `F → A` 流程以實測 Wiki 與系統擴充性。
